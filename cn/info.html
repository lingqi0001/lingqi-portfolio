计算机工程与电子电气工程 (CE / EE)

我最初并不是从硬件或电子工程开始的。高中前期，我最感兴趣的是 User Experience、Human-Computer Interaction 和软件开发，因为我喜欢从一个很具体的问题开始：人为什么觉得某个系统难用？一个功能为什么明明存在，却没有真正帮助到使用它的人？我习惯先观察人的行为，再去调整界面、信息结构和交互方式，最后把想法做成真正可以使用的产品。

CHSchat.xyz 是这种思路发展得最完整的项目之一。

它最开始可以被理解成一个面向 Centennial High School 学生的 communication platform，但在不断开发的过程中，我逐渐不再把它看成一个单独的聊天软件。我希望把学校里原本分散在不同网站、页面和流程中的东西重新组织到一个更统一的系统里。因此，CHSchat 后来逐渐包含了 school news、club information、events、messaging、Eagle Time、grade calculator、cafeteria menu、peer tutoring、suggestions、lost and found、marketplace，以及面向未来扩展的 developer tools。登录系统也需要适应学校真实使用的 HCPSS Microsoft accounts，而不是只在我自己的开发环境里“能够登录”就算完成。

这个项目让我第一次非常明显地感受到：设计一个体验更好的产品，和让这个产品真正进入现实环境，是两件完全不同的事。

在电脑上，我可以不断修改页面、功能和交互。我甚至可以根据一个老师的实际需求去定制某一部分软件。但当我真正考虑怎样让这样的系统被更多学校使用时，我开始碰到一些单靠 UX 或 web development 很难解决的问题。

原有平台已经储存了大量数据，学校不会因为一个新软件体验更好，就轻易放弃原来的系统；不同学校使用的账号体系、设备和技术环境也完全不同。在 Centennial，Chromebook 和学校账号已经成为数字学习环境的一部分，但当我重新考虑中国学校的使用场景时，情况又不一样。有些学校没有一套可以让每个学生随时使用的 Chromebook 或类似设备。一个建立在“每个人都有自己的浏览器和个人设备”这个假设上的产品，即使软件本身设计得很好，也可能从一开始就没有部署的条件。

这件事改变了我理解“User Experience”的方式。

以前我会把问题想成：怎样把这个 interface 做得更好？

后来我开始问：如果这个 interface 根本没有合适的设备承载它怎么办？如果真正限制用户的不是页面，而是他们手里根本没有一个适合完成这件事的工具怎么办？

这也是我开始接触硬件的原因。

我尝试制作价格更低、功能更专一的课堂答题器，以及使用 e-ink display 的沟通设备。与其要求学校先拥有一套完整的个人计算设备，我开始思考能不能针对一个具体需求，直接设计一个足够便宜、足够简单、可以大量部署的 physical device。

目前这些原型仍然大量依赖现成的 microcontrollers、display modules 和其他 off-the-shelf components。我可以把它们连接起来，编写软件，让一个 prototype 工作，但这个过程反而让我越来越清楚地看到自己的知识边界。如果我要把几个开发板和模块拼成的原型进一步变成一个真正紧凑、稳定、低成本、适合大量制造的产品，我不能永远停留在 assembly 的层面。

我需要理解 PCB 是怎样设计的，电路为什么这样连接，电子元器件怎样选择，电源和通信怎样处理，firmware 怎样与底层硬件配合，以及软件、电子系统和最终的 physical form 怎样被设计成同一个产品。

因此，对我来说，从 HCI/UX 转向 Computer Engineering / Electrical Engineering 并不是放弃过去的方向。恰恰相反，是我在不断把过去的问题往更底层追问。

我从“这个界面怎样更好用”，走到了“这个系统怎样真正被采用”，最后又走到了“支撑这个体验的设备本身应该怎样被设计”。

Computer Engineering 吸引我的地方，正是它位于 software 与 hardware 的交界处；Electrical Engineering 则能够让我真正理解 circuits、electronics 和构成这些设备的底层原理。这两条路径都能补上我现在最明显缺少的一块能力。

我的目标并不是离开 User Experience，成为一个只关注电路参数或者只关注代码是否运行的工程师。

我反而希望保留自己已经形成的那种工作方式：先找到人的问题，再决定应该用什么技术解决，而不是先拥有一种技术，再寻找可以把它放进去的地方。

CHSchat 对我来说是一个很重要的起点，因为它让我学会怎样从学生和老师每天真实经历的摩擦出发，把很多零散的问题重新组织成一个系统。但它也让我认识到，一个产品最终是否有价值，并不只取决于它的 interface 是否直观。成本、设备条件、兼容性、维护、数据迁移、学校现有的 infrastructure，甚至一个老师愿不愿意改变自己已经使用多年的 workflow，都可能决定一个设计最终能不能存在于现实中。

所以大学阶段，我希望补上自己目前无法独立完成的工程部分：circuits、PCB design、embedded systems、computer architecture、electronics、firmware，以及 hardware-software integration。

更长期来看，我希望拥有一种从问题一直做到产品底层的能力。

当我发现一个老师需要更简单的课堂互动方式时，我不希望自己的选择只有“再做一个网页”；当某个学校没有足够的个人计算设备时，我也不希望只能得出“这个软件无法部署”的结论。我希望自己能够继续往下设计——改变通信方式，改变设备结构，重新考虑成本，甚至重新设计承载这个 interaction 的硬件本身。

我想做的不是为了证明技术复杂而复杂的产品。

我更感兴趣的是那些看起来也许很普通，但能够真正进入人的生活的东西：一个学校买得起的课堂设备，一个老师不需要重新学习整套系统就能使用的工具，一个学生拿起来几秒钟就知道应该怎么操作的产品。

最终，我希望把 UX/HCI 对人的理解、software development 的实现能力，以及 CE/EE 对 physical technology 的控制能力 放在同一个过程中。

对我来说，真正完整的产品设计应该可以从一句：

“这里为什么这么难用？”

一直走到：

“那我们能不能重新设计它？”
